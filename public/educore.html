Clear Answers for
School Administrators.

How does the 50m Geofence function with less than 1% battery drain? expand_more
EduCore uses Android's Fused Location Provider sensor hub. When a user is more than 1 km away, the GPS chip remains 100% OFF and location is passively monitored via cell towers. Wi-Fi router beacons monitor the 200m–500m vicinity. Only when the device crosses the 50m school boundary does high-precision GPS wake for 2 seconds to log coordinates, after which it immediately powers back OFF.
What happens if attendance is marked while mobile data is disconnected? expand_more
EduCore includes an offline SQLite persistence queue. If mobile data is disabled, the arrival timestamp and biometric vector are safely stored locally in encrypted SharedPreferences. As soon as the device reconnects to Wi-Fi or mobile network, the background sync engine pushes records to the Turso cloud database automatically.
How does EduCore protect database credentials inside the Android APK? expand_more
Unlike traditional apps where database tokens are compiled into the binary, EduCore features a Zero-Secret Mobile Architecture (src/turso.js). All queries route via an authenticated Vercel Edge proxy. The mobile app contains zero database secrets. Furthermore, dangerous operations such as DROP or ALTER are blocked server-side.
Can students call each other directly on the VoIP engine? expand_more
No. EduCore enforces a strict Institutional Access Policy. Student-to-student direct calling is permanently blocked client-side and server-side with an HTTP 403 Forbidden check. Voice calls are strictly permitted between Students and Teachers, or inside teacher-moderated Class Doubt Clearing voice rooms.
How do updates deploy without waiting for Google Play Store review? expand_more
EduCore utilizes a Two-Stage Silent Background OTA Push Engine. Critical bug fixes and UI upgrades are packaged as optimized React Native JavaScript bundles and broadcast via high-priority FCM. Devices download the bundle silently in the background and reload the React context on next wake without requiring user intervention.
